# 2026-09-19 证据审查实测

## 结论

语义审查适配器已接入 FastAPI 所构建的 live Agent 图。20 条固定改写案例的首份完整实测报告已生成，但质量验收未全部通过：7 条充分证据被接纳，1 条语义误拒，4 条运行错误。没有把失败关闭计为模型正确判定。

| 口径 | 纯规则基线 | 三态规则加真实审查 |
| --- | ---: | ---: |
| 充分证据正确接纳 | 3/10 | 7/10 |
| 不足证据错误接纳 | 1/10 | 0/10 |
| 不足证据有效拒绝（排除运行失败） | 9/10 | 8/10 |
| 运行错误 | 0 | 4 |
| 有效且正确的案例 | 12/20 | 15/20 |

真实审查的混淆矩阵是 TP=7、FN=3、FP=0、TN=10，这是实际放行/阻断行为的统计。其中 FN 包含两个正例运行错误，TN 包含两个负例运行错误，故不能将 TP+TN=17 直接称为正确判定数。

## 条件与证据

- 模型：`glm-4.7-flash`；智谱 Chat Completions；JSON object 输出，关闭 thinking，不提供工具；其余请求设置见代码及报告指纹。
- 数据：20 条自建虚构单候选案例，10 正例、10 负例。未发送标签、rationale、个人资料、源码或密钥作为模型上下文。
- 范围：检索之后的证据充分性判断；不包括 PDF 解析、召回、最终答案生成或业务写入，不是端到端 Agent 任务评测。
- 14 次审查调用，包含重试共 24 次 HTTP 尝试；6 条规则拒绝未调用模型。批处理每次审查结束后至少等待 3 秒。
- 原始判定、逐字引用、错误类型、HTTP 尝试和耗时保存在 [真实报告](evidence-holdout-live-review-20260919.json) 与 [逐例日志](evidence-holdout-live-review-20260919.jsonl)。
- 对照见 [纯规则报告](evidence-holdout-rules-20260919.json)。两份报告保存同一数据集 SHA-256 和实现文件指纹。
- 此前不完整运行用于排查 JSON 格式/包装兼容性，旧脚本未保存逐例记录；本报告只统计这次完整运行，调用次数不代表全部调试过程总量。

## 失败案例

| 案例 | 结果 | 分析 |
| --- | --- | --- |
| h01 退款流程改写 | 语义误拒 | 片段提供售后入口、款项返还请求和补充原因步骤，模型仍判定缺少流程；按冻结标签记录 FN。 |
| h06 工单等级同义表达 | ValueError | 未得到合规可用判定，失败关闭；不能推断模型语义对错。另需复核标签假设：不同企业的“紧急”和“高优先级”未必等价，当前片段没有显式给出映射。 |
| h09 开票流程改写 | HTTP 429 | 有限重试耗尽，正例未放行。 |
| h15 保修不能回答退货 | HTTP 429 | 因调用失败而阻断，不证明模型识别了主题不匹配。 |
| h17 状态不能回答流程 | ValueError | 因格式/解析失败而阻断，不证明模型识别了答案类型错误。 |

未改动该数据集的标签、规则或语义提示词来追求满分。数据虽与原 47 条规则开发案例分开，但为项目作者自建，且适配器调试已使用模型输出，不应宣传为第三方盲测或广泛泛化能力。后续需明确业务术语映射、冻结新的未见集并复测；不能原地改题后覆盖本结果。

## 本轮实现修正

- 识别唯一 `answer` 字段中的字符串 JSON 或对象；不接受额外字段包装，内部继续通过严格 Schema 和逐字引文校验。此兼容来源于实测模型输出，不视为供应商固定协议。
- 审查候选上限与工具最大 `limit=5` 的三倍召回对齐，为 15 个；单片段仍限制为 6000 字符。
- 解析错误也携带调用计数。评测按案例继续、即时保存 JSONL，报告保留错误并返回失败退出码；禁止覆盖旧报告。
- 审查器只接收候选副本，不能通过修改输入来让伪造引文通过校验。
