# 账号、历史会话与图片问答

## 使用入口

访问 `/demo`，用本机初始化的账号登录；`/service` 提供固定订单办理，复用同一个登录Cookie。旧手动令牌演示 `/demo/legacy` 默认关闭，显式启用后仍须 developer 角色；Bearer 不能替代售后门户登录。

先按README启动数据库与应用，再执行一次非破坏性初始化：

```powershell
python scripts/initialize_customer_portal.py --initialize-missing
```

脚本要求本机Python依赖和DATABASE_URL已配置。它仅创建缺失的表/演示账户，不重设已有密码。随机密码只写入被Git忽略的 `output/customer-login-access.txt`，不打印到终端；不要将该文件上传、截图分享或提交。初始化账号映射到服务端既有U-1001/U-1002/U-admin身份；管理员 `ys10087` 由本机维护初始化，需配置 U-admin 身份。

2026-10-28 起开放本机自助注册：在 `/demo` 点击“没有账号？注册”，账号为3—40位英文字母、数字、下划线或连字符，密码12—128字符。注册后自动登录，只获得普通用户权限，并在同一数据库事务中创建一笔虚构演示订单及商品政策。页面显示本人的演示订单号。订单号使用 O-8000 至 O-9999，本机最多分配2000个演示订单；容量满时明确拒绝注册。

已有数据卷更新时执行 `python scripts/upgrade_portal_accounts.py` 应用005并设置约定管理员；它保留密码、订单和聊天。脚本要求 `ys10087` 已绑定本机配置的 `U-admin`，其他身份即便注册同名账号也不会被提升。普通注册不能选择角色、用户ID或订单归属。注册按地址15分钟最多10次尝试；登录另按原账号/IP窗口控制。第一版没有手机/邮箱验证，也没有自助密码找回，不应当作公网生产身份系统。

管理员登录后顶部显示“用户管理”，支持每页50条用户、角色和启用状态，以及显式确认后的启用/禁用。禁用立即撤销该账号所有会话；重新启用不会恢复旧会话。不能禁用本人或最后一个可用管理员；不提供网页创建管理员、修改角色或删除历史功能。用户管理与上传政策均只给管理员。

也可在API容器内执行同一脚本，再将生成的密码文件复制到本机：

```powershell
docker compose exec -T api python scripts/initialize_customer_portal.py --initialize-missing
docker cp opspilot-api:/app/output/customer-login-access.txt ./output/customer-login-access.txt
```

已有账号不会重新生成密码；原密码文件丢失须由管理员显式处理，不能靠重新初始化恢复明文。

## 登录与权限边界

- 密码使用带独立随机盐的scrypt哈希，不保存明文；登录失败统一错误，按账号及客户端地址执行共享数据库计数。
- 浏览器使用8小时硬到期的随机HttpOnly/SameSite=Strict会话Cookie；数据库只保存会话哈希。退出后删除服务端会话，旧Cookie不能重用。没有自动续期。
- Cookie修改请求须有匹配的CSRF请求头，并校验浏览器Origin/Fetch-Site；登录也拒绝跨站来源。登录校验错误不回显密码。
- 账号角色以数据库记录为准；门户向Java发起业务请求时签发30秒HS256身份断言，固定issuer/audience，签名密钥从内部服务凭据按独立用途派生。仅受控Java客户端附带断言与内部服务令牌，浏览器、历史正文和视觉模型拿不到。Java验证签名/期限后还查询账号是否启用，再校验订单归属；处理中被禁用的账号后续Java调用同样拒绝。
- Java继续独立校验订单归属、政策、快照和事务，不接受聊天或图片里的“已经授权”。既有服务端静态令牌保留兼容；不要分发给浏览器或模型。
- 等待当前回答时可继续输入下一句话，但不并发发送；完成/轮询不得清空新草稿。切换会话或新建会话前提示未发送内容，可取消切换。草稿不持久保存，刷新页面会丢失。
- 本机API端口仅绑定127.0.0.1。HTTP演示Cookie默认不带Secure；非本机部署必须使用HTTPS并配置 `PORTAL_SECURE_COOKIES=true`，不能直接将本演示当作生产认证系统。

## 历史会话与执行恢复不是同一份数据

- PostgreSQL保存用户可见的问题、回答、图片、关联任务编号与状态；不保存系统提示词、原始模型请求、密钥或内部授权头。
- Redis/LangGraph仍保存执行检查点。检查点过期后可以阅读历史，但不能根据旧聊天自动重建确认或重复写入。
- 每次追问创建新任务，结合最近3轮、带来源的用户原文摘要和当前会话内语义召回构建有界上下文；旧订单状态/金额必须重新查询，旧工具和批准不重放。摘要可能丢失细节，保留原文查询入口；参见[上下文管理](conversation-context.md)。
- 单一订单指代可延续；多个订单不擅自选一个。明确退货上下文中的“那帮我申请”只产生新草稿，并再次等待确认，不代表批准。
- 每轮带请求UUID，同一UUID/同一内容只返回原消息；同一UUID换内容拒绝。会话行锁只用于登记短事务，执行模型时不长期持有数据库事务。
- 同一会话不并行执行两次操作。结果未知时阻断新任务，先按原任务同步；同步本身不会重放工具。服务崩溃时登记可能停留RUNNING，15分钟内保守认为可能仍在执行；之后仍只读取检查点，无法确定时要求人工核对，不宣称任意故障自动恢复。
- 历史按50轮游标分页，已移除每会话100轮硬上限；每用户仍最多200个会话、100张图片且总计不超过100MB。未实现面向任意账户规模的注册、密码找回、自动归档和保留期管理。

## 直接多模态链路

```text
登录 → 新建/打开本人会话 → 上传1–3张图片 → 验证并去元数据 → PostgreSQL私有存储
     → 输入问题 → 本地视觉模型直接读取图片与有界历史（云端配置须本轮外发同意）
     → 校验问答格式 → 展示观察与不确定性
     → [可选]已发布PDF检索/证据复核 → 程序附上原文和页码
```

- 输入是PNG/JPEG，每张最多4MB、边长最多6000且最多1200万像素；核对真实文件格式、拒绝动图/损坏文件，重新编码去除EXIF及尾随数据。
- 图片以受保护ID访问，只能属于当前用户及会话。没有公开静态图片目录，不提供用户URL下载接口，避免引入任意URL抓取/SSRF。
- 已验证图片直接作为 `image_url` 的base64 data URI输入视觉模型，**不是必须先OCR，再嵌入检索**。图片不自动加入公共PDF知识库。
- 支持同轮多图及显式沿用上轮图片；历史回答用来理解问题，原图片仍作为视觉输入。不把上轮文字描述当作再次看过图片。
- 默认由本机 Ollama `qwen3-vl:4b` 接收图片；显式云端配置使用 `glm-4.6v-flash`。所有HTTP尝试通过Redis共享配额，本地单次视觉调用1次HTTP，云端最多2次，失败不换模型。
- 视觉返回只允许结构化观察、回答及不确定性，收到工具动作或非法格式拒绝；视觉路径没有业务工具执行器，不能确认退款。
- 若用户希望结合政策，程序分别展示视觉推断和经现有证据门禁核对的政策摘录；图片无法证明订单归属、商品真伪、法定责任或最终退货资格。业务办理仍走Java规则和显式确认。
- 模拟模式只验证控制流并明确标注“未分析图像”，不把模拟描述当作识图能力证据。

## 本地视觉与可选云端配置

默认Compose使用本机Ollama；模型与本地资源准备见[运行说明](local-model-runtime.md)。本地视觉不会请求云端授权，也不自动回退云端。

先确认本机智谱配置以及图片外发授权，再使用可选覆盖文件：

```powershell
docker compose -f docker-compose.yml -f docker-compose.vision.yml up -d --no-deps --no-build api
```

覆盖文件显式选择云端并从本机环境注入ZHIPU_API_KEY，不写入镜像或代码；普通用户不能自行切换供应商，图片须逐轮外发同意。默认Compose不注入云端密钥。不要上传真实证件、银行卡或未脱敏订单。

历史云端合成图验收遇到连续HTTP429，2次请求后停止，原始记录见[云端识图冒烟](../reports/vision-live-smoke-20261021.json)。2026-10-24本地Ollama正确识别两张合成色块/文字图，见[本地校准](../reports/context-validation-20261024.md)；这些小样例不代表真实售后图片准确率。

官方协议与模型说明：[GLM-4.6V-Flash](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.6v-flash)、[对话补全](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)。

## 本机复现

“新会话”只打开浏览器草稿，不立即创建数据库记录；第一条问题或图片上传才创建。
创建请求网络失败时沿用原会话UUID，后端重复请求返回原记录，不覆盖标题。
只有存在消息轮次的会话进入历史；附件未发送的草稿与旧空白会话不展示，
但不删除原数据。回答失败的实际问题仍保留，便于同步和排查。

部署模式下“直接办理售后”须使用门户账号会话，旧调试令牌不能替代登录。
未登录访问 /service 会跳回 /demo，API返回401；写操作仍要求CSRF和同源校验。
用户页不展示开发调试入口。调试页、原始Agent HTTP接口及API文档默认关闭；
只有显式开启 OPSPILOT_DEBUG_ENABLED 并配置独立 developer 角色才开放。
knowledge_admin 仅负责知识库，不自动获得开发调试权限。

本机 Compose 的 API、Java、PostgreSQL 和 Redis 映射端口均绑定 127.0.0.1。
这不替代鉴权或 Redis ACL；当前配置不得直接用于公网或不可信多租户环境。
图片任务若一直执行，可点击“同步原任务状态”：15分钟以内保留活动任务，
超时后在事务内标记失败并释放该会话，不自动重发图片、模型或业务请求。
旧请求的迟到回包不会覆盖已终止状态；业务任务仍须核实原检查点和业务结果。
验收脚本按 U-1001/U-1002 查询当前用户名，预置账号改名不会改变订单归属；
本机账号文件应同步更新，但不能提交密码。

离线：运行 `tests.test_customer_portal`、前端 `static/portal.test.cjs`；真实PG测试需显式 `RUN_PORTAL_POSTGRES_INTEGRATION=1`，只创建随机隔离schema，完成后清理。

部署冒烟：`python scripts/smoke_customer_portal.py`。使用合成图片、临时订单和mock，验证登录、历史追问、图片/政策联查、确认及重复请求，清理自己的临时会话/订单；测试检查点在Redis按原TTL过期。不会外发图片或调用供应商。

真实视觉小批脚本须重新获得数据/预算授权后才能运行 `scripts/verify_vision_live.py --approved-synthetic-batch`；不能把历史授权当作无限次复测许可。
