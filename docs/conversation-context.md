# 会话上下文与长度预算

## 数据流

门户先按认证身份读取本人当前会话，不跨用户或跨会话检索。PostgreSQL 保留原聊天记录；模型只接收选出的参考内容，裁剪不会修改数据库历史。

1. 近期对话：优先最近三轮可见消息。有旧历史且当前问题非空时，最多使用历史预算的 60%，避免近期长闲聊挤掉相关旧信息。
2. 按需旧文：保留关键词/明确订单号筛选，并可启用本地 BGE-small-zh-v1.5 语义召回。派生向量保存在 PostgreSQL 的 `portal_turn_memory`，仅检索本人当前会话；读取原消息并核对来源指纹后，才作为不可信参考候选。明确询问一个订单时，仍排除其他订单参考。
3. 早期摘要：从其余旧用户消息做确定性原文抽取，带来源编号，明确不是模型摘要。预算不足时只保留完整句并标记摘录不完整；不是承诺完整保留语义。
4. 模型前预算：将系统提示、当前问题、历史、工具定义、工具调用/结果、结构化输出格式及预留输出一起计算。文字、视觉、证据审查均经过该入口。

历史参考最多 6000 个 UTF-8 字节（包括 JSON 序列化开销），这是历史选择预算，不是模型 token 总量。配置 `QWEN_TOKENIZER_PATH` 后，从已安装 Qwen3-VL 导出的实际 BPE 词表，对按 Ollama 模板渲染的文本计数；校验资产版本和 SHA-256。模板已核对 Ollama 0.40.5 / 0.40.9；其他模型或未配置分词资产时仍为保守估算，不能泛称精确计数。

本地 `num_ctx` 为 8192，输出预留为文字 512、图片 2048、结构化审查 4096。图片另预留每张 1024 单位，不将 base64 当文字；这不是精确视觉 token 数。请求设置 `truncate=false`、`shift=false`，禁止自动裁剪/上下文滑动；后端实际超窗返回明确错误。响应记录实际 `prompt_eval_count` / `eval_count` 供校准，拒绝负数或总量超窗。2026-10-24 完成五类文本计数校准，见下文。

## 超长时的行为

先移除抽取摘要，再移除低优先级近期历史，最后移除按需旧文；同优先级先移除更早记录。只允许删除服务端标记的可选历史。

当前用户问题、系统策略、工具调用与结果配对、正式政策证据都不硬截断。移除历史后仍超预算，抛出 `ContextBudgetExceeded`，在配额准入及 HTTP 发送前停止，不重试、不切换模型。门户保存 `FAILED` 并释放活动任务标记，返回 422 和缩小问题范围的提示，不误记为业务结果未知。

一次长任务前面已经完成的只读查询不因此撤销；预算拒绝只证明本次模型请求未发送，不能宣称整个任务从未做过查询。不会自动提交、取消或重新创建申请。

## 事实、权限和确认不依赖摘要

- 所有历史重新包装为 `user` 级不可信参考，不能冒充系统策略或工具消息。
- 只读取可见正文及安全来源编号，不复制 `approved`、草稿、私有工具轨迹、身份令牌等状态。
- 订单号的历史指代仍须重新查询业务服务；资格、金额、草稿期限和确认快照继续由既有服务端状态及 Java 业务校验决定。
- 即使历史回答声称“已经确认”，也不设置当前任务的 `approved`，更不会自动确认。
- 抽取摘要按需重新计算，不调用大模型。语义召回另需迁移 004 和本地 Embedding 资产；原聊天不改写。摘要不保证无损，需要完整信息时可通过归属校验的原消息接口读取。

## 明确的限制

本地文本已接入模型词表和模板计数，2026-10-24 在普通文本、工具定义、工具结果、JSON 和长中文五例上与实际推理用量一致；这不是任意模型、任意消息格式的普遍证明。视觉部分仍需后端拒绝超窗兜底，不能承诺任意图片都能在窗口内处理：两张 336×336 合成图的实际 prompt 为 1044，估算为 1042，保留差异记录。云端/其他模型保留保守估算，未来须按对应供应商接入计数能力。

已移除每会话 100 轮硬限制，历史采用 `(created_at,id)` 游标分页，每页 50 轮；原请求号可直接查回，不依赖其是否在当前页。保留活动任务、幂等及身份隔离。2026-10-24 完成真实 PostgreSQL 集成及部署 HTTP 验证，137 轮按 50/50/37 返回，旧请求与原文可找回，跨用户拒绝访问。语义召回每次最多补建 32 条来源索引；大量旧会话可使用有批次数上限的管理脚本补建，首次请求不会一次性扫描全部历史。

单个会话语义搜索不是跨会话长期人物记忆；Embedding 只帮助选取参考，不能证明旧信息正确。索引故障时返回可识别失败并释放活动状态，不假装召回成功。

## 资产与迁移

在安装了 `qwen3-vl:4b` 的本机运行 `scripts/export_context_tokenizer.py` 导出词表，不下载语言模型权重。经明确批准后可运行 `scripts/cache_memory_embedding.py` 下载固定 revision 的 BGE ONNX 及配套文件，约 95.3 MB；运行时 `local_files_only=True`，不自动下载。

Compose 将 `.models/context-tokenizer` 和 `.models/memory-bge` 只读挂载到 API。新环境先执行 003，再执行 `db/migrations/004_conversation_memory.sql`；004 仅新增派生语义表及查询索引，不更新订单或申请。已有数据库不会因重建容器自动执行迁移，须单独执行。部署失败保留原镜像及数据；不要删除数据卷。

管理脚本 `scripts/backfill_conversation_memory.py` 要求明确 user-id / conversation-id / max-batches，仅对指定来源建立派生索引，不调用大模型、不赋予用户权限。

`scripts/verify_context_live.py --allow-local-inference` 使用冻结的虚构文本、工具消息和两张生成图。每次尝试前保存预算账本，并经过独立 Redis 限流；同批最多 12 次，不自动重试或切换云端。需要用户单独授权，未授权时不能运行。

验收脚本拒绝覆盖已有报告。真实校准使用原批次账本与独占锁；不要删除账本或残留锁来绕过预算。残留锁须先确认没有执行中的验收，再由操作者处理。部署验收可用 `scripts/verify_context_deployment.py --output reports/<新的文件名>.json` 指定新报告；默认历史路径已存在时会在创建测试数据前拒绝执行。
