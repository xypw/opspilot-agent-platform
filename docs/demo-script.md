# OpsPilot 三分钟演示脚本

## 0:00-0:30 说明业务问题

电商售后既需要从政策文档中找依据，也需要查询订单并执行退货。模型适合理解意图和组织回答，但正式业务写入必须由确定性服务校验，并在用户确认后执行。

## 0:30-1:10 演示知识问答

1. 打开 `/demo`，上传仓库中的虚构售后政策 PDF。
2. 提问“紧急退款审核通过后多久到账？”
3. 展示回答中的资料标题与页码，说明文档切块、检索、证据门禁和程序化引用。
4. 提问一个知识库外问题，展示证据不足处理。

## 1:10-2:20 演示退货申请

1. 输入虚构订单并说明退货原因。
2. 展示 Agent 的工具轨迹：查询订单、创建草稿、等待确认。
3. 强调此时 Java 数据库中还没有正式申请。
4. 选择拒绝，展示零写入；重新发起后选择确认，展示申请编号。
5. 重复确认同一草稿，展示返回同一申请而不是重复写入。

## 2:20-3:00 展示可靠性证据

1. 打开 `reports/2026-09-13-integration.md`，说明四服务模拟模型 7/7 与真实模型 4/7 的边界。
2. 打开 `reports/rag-offline-evidence-v2.json`，说明固定回归集中旧规则的 21 条误放行如何降为 0。
3. 说明真实 Reranker 在 11 条简单正例上没有测出增益，因此保留原始结果而不夸大。

演示只使用虚构数据；不要展示 `.env`、API Key、个人订单或真实客户资料。
